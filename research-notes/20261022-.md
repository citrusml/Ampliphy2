## 1. 環境構築の全体概要と基本方針

本環境は **LSF（IBM Spectrum LSF / `bsub`, `bjobs`）** をジョブスケジューラとするスパコン環境を前提とし、パッケージ管理には **`micromamba`** を使用する。

主要な構成要素は以下の通りである：
1. **`micromamba`**: 軽量かつ高速な Conda 互換パッケージマネージャ
2. **`foldtree` 環境 (Python 3.10)**: 配列抽出 (`01_prepare_input.py`)、系統樹トポロジー解析、および TCS (Tree Certainty Score) 算出 (`fold_tree`)
3. **`biotools` 環境**: MAFFT (MSA), IQ-TREE 2 (ML系統樹推定), MMseqs2 (相同配列検索), GoTree (プルーニング), Nextflow (ワークフロー管理), OpenJDK 17
4. **MAD v2.2 (Minimum Ancestor Deviation)**: 系統樹のルート決定（ルーティング）ツール
5. **GS法 (`gs2`)**: Graph Splitting 法による新規系統樹構築ツール（C++17 / LAPACK / OpenMP / MMseqs2連携）
6. **LSF ジョブ投入設定**: Nextflow およびバッチジョブスクリプトの LSF 分散並列設定

## 6. Step 4: GS法 (`gs2`) 解析環境の構築（今回新規追加）

[MotomuMatsui/gs](https://github.com/MotomuMatsui/gs) は、C++17、LAPACK/BLAS、OpenMP、および全対全ペアワイズアライメント用の MMseqs2 に依存する。

### (1) ビルドに必要なコンパイラ・ライブラリの準備
スパコンの標準 GCC（5.0 以上、C++17 対応）を利用するか、Conda 環境から導入する。

```bash

```

### (2) `gs2` のクローンとコンパイル

```bash
cd "$WORK_DIR"
git clone https://github.com/MotomuMatsui/gs.git "$WORK_DIR/gs"
cd "$WORK_DIR/gs"

# biotools 環境内でコンパイルを実行
micromamba run -n biotools make

# ビルドされた gs2 バイナリの確認
./gs2 --help || ./gs2 -h
```

次に
今回は
https://github.com/MotomuMatsui/gs
で作られているgs法においてTCSが向上するかを調べるためのスクリプトを作成する。
スクリプトは以下のpathに保存した。


- コアロジック / 評価モジュール	
  - ``src/gs_pipeline.py``
  - 配列の非整列化（Unalign）、gs2 コマンド生成、Newick樹の整形、追加ホモログのID抽出、TCS改善度（$\Delta\text{TCS}{\text{ratio}}, \Delta\text{TCS}{\text{diff}}$）の算出およびWilcoxon検定を行うPythonモジュール。

- スパコン実行スクリプト	
- ``scripts/run_gs_pipeline.sh``
  - LSFバッチジョブ（bsub < ...）および対話型シェル実行に対応した一括実行シェルスクリプト。配列前処理から gs2 実行、MADルート化、GoTree枝刈り、TCSスコア計算・集計までを一気通貫で実行。
  
Step 1: 配列の非整列化（Unalign）とヘッダー正規化
ギャップ文字（-, .）を除去し、生配列FASTAを作成。ヘッダーの余分な空白を除去してID整合性を担保。
Step 2: GS法 (gs2) による系統樹推定
オリジナル配列およびホモログ追加後配列のそれぞれに対し、``gs2 -l -t 16 -m 7.5 -s <input.fa> > <output.nwk> ``を実行（-l によりNewickにFASTAヘッダー名を出力）。
Step 3: クリーンアップ & 第一分割ルートの採用（MAD不使用）
PhyloMethod_Comparison の知見に基づき、GS法（gs2）はトップダウンの再帰的2分割法であるため、出力される最外殻の2分割（第一分割）がそのまま自然な根（Root）となる。そのため MAD による再ルーティングは行わず、第一分割を根としてそのまま採用する（Newick構文のクリーンアップのみ実施）。
Step 4: GoTree による追加ホモログの枝刈り（Pruning）
追加されたホモログ配列（UniRef50配列等）のみを ``gotree prune -f homologs.txt`` で切り落とし、第一分割の根構造を保持したまま、オリジナル樹と完全に同一の葉集合を持つ Pruned 樹（Enriched樹）を作成。
Step 5: TCS スコアの算出と集計
foldtree 環境で ``ampliphy-analysis/scripts/tcs_batch.py`` を実行し、オリジナル樹（aug）とホモログ追加後樹（enr）の TCS スコアを算出。
改善比率 ``$\Delta\text{TCS} = \frac{\text{TCS}{\text{enr}}}{\text{TCS}{\text{aug}}}$``、スコア改善HOG割合（%）、Wilcoxon符号順位検定による有意差（p-value）を自動集計・出力。
gs法を実行するためには、比較対象となるホモログ追加後MSA（`*.amp.fa`）が必要である。
そのため、まずは AmpliPhy（Nextflow）を実行してホモログ検索（MMseqs2 on UniRef50）および追加MSA作成（MAFFT `--addfragments`）を行うスクリプト ``scripts/run_ampliphy.sh`` を作成した。

### AmpliPhy 実行手順
1. **動作確認（サンプルデータ 5ファミリー）**:
   ```bash
   bsub < scripts/run_ampliphy.sh
   # または対話型
   bash scripts/run_ampliphy.sh sample
   ```
   初回実行時に UniRef50 データベースが自動でダウンロード・構築され、`sample/output/msa/` に `*.amp.fa` が生成される。
2. **本番データ（Eukaryota, Amniota, Bacteria, Actinomycete）の実行**:
   ```bash
   # 単一種
   bash scripts/run_ampliphy.sh eukaryota
   # 全4種一括
   bash scripts/run_ampliphy.sh all
   ```
3. **増幅後MSAを用いたGS法パイプラインの実行**:
   AmpliPhy により各生物種の `results/<taxon>/msa/*.amp.fa` が生成された後、``scripts/run_gs_pipeline.sh`` を実行してGS法による系統樹推定とTCS改善度の評価を行う。
defaultのampliphyを一旦回すことにした。defaultでは配列の集め方に細かい指定はなかった。

また新たに気づいたことだが以前の時もmafftはaddfragmentをデフォルトとして動いていた。なので以前の結果はaddfragmentでの結果であった。

ampliphyのスクリプトがtcsスコアを同時に計算する仕組みになっていたのでtaxonomyファイルが必要であった。色々と環境が変わったことにより変更点があったが、修正を行ってなんとか動くようになった。
